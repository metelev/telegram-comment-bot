# Telegram comment bot

Бот отвечает на текстовые сообщения и фотографии естественным комментарием через GigaChat. В группах отвечает на упоминание, ответ боту или автоматически пересланную запись канала.

## Память разговора

Бот хранит до 20 последних сообщений участников и своих успешно отправленных ответов в SQLite. Личные чаты, темы форума и обсуждения разных постов разделены; известные цепочки ответов сохраняют привязку после перезапуска. Сообщения без обращения к боту тоже попадают в память, если Telegram передаёт их боту.

В GigaChat отправляется до 12000 символов истории, до 2000 символов на сообщение. Старые тексты сверх лимита удаляются; для распознавания вложенных ответов остаётся до 2000 привязок сообщений на чат. У старых фото доступны только подписи и отметка о фотографии, сами изображения не хранятся. Текущее фото анализируется как раньше.

История начинается после запуска этой версии. Бот не загружает старую переписку. `drop_pending_updates=True` пропускает накопившиеся обновления при запуске. Если родительские сообщения не были получены, неизвестная цепочка ответов хранится отдельно, а не объединяется с другим обсуждением.

Для получения обычных сообщений группы бот должен быть её администратором либо иметь отключённый Privacy Mode в BotFather. См. [документацию Telegram](https://core.telegram.org/bots/features#privacy-mode).

## Настройка

Нужен Python 3.10 или новее (на сервере используется Python 3.12). Скопируйте `.env.example` в `.env` и заполните:

- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота;
- `GIGACHAT_CREDENTIALS` — ключ авторизации GigaChat;
- `TELEGRAM_PROXY_URL` — адрес локального прокси, например `http://127.0.0.1:12334`; пустое значение отключает явно заданный прокси;
- `CONTEXT_DB_PATH` — необязательный путь базы истории, по умолчанию `data/context.sqlite3` рядом с `bot.py`.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python bot.py
```

Тональности и вероятности: дружелюбный с лёгкой иронией — 60%, нейтральный — 10%, дружелюбный — 5%, лёгкий юмор — 15%, дерзкий — 5%, милый — 5%.

## Запуск на сервере

Проект устанавливается в `/opt/projects/telegram-comment-bot`. Для службы `deploy/telegram-comment-bot.service` должны существовать пользователь и группа `telegram-comment` и быть запущен прокси `hiddify-paper.service`. Подписка VPN настраивается отдельно и не хранится в репозитории.

Каталог базы должен быть доступен пользователю службы для записи:

```bash
install -d -m 750 -o telegram-comment -g telegram-comment /opt/projects/telegram-comment-bot/data
cp deploy/telegram-comment-bot.service /etc/systemd/system/telegram-comment-bot.service
systemctl daemon-reload
systemctl enable --now telegram-comment-bot.service
```

Если используется собственный `CONTEXT_DB_PATH`, разрешите его каталог для записи пользователю службы и в `ReadWritePaths` systemd. `.env` должен быть доступен для чтения пользователю службы.

При обновлении нужно переносить вместе `bot.py` и `context_memory.py`, сохраняя `.env` и каталог `data`. Для базы SQLite новые зависимости не требуются.

```bash
systemctl restart telegram-comment-bot.service
systemctl is-active telegram-comment-bot.service
journalctl -u telegram-comment-bot.service --since '5 minutes ago' -n 60 --no-pager
```

Статус `active` означает только работающий процесс. Проверьте ответ в Telegram: «Едем в Казань», затем «Что там посмотреть?». После перезапуска спросите «А что там попробовать из еды?» — контекст должен сохраниться.

## Тесты

```bash
.venv/bin/python -B -m unittest discover -s tests -v
```

18 тестов проверяют сохранение истории, разделение чатов и обсуждений, цепочки ответов, лимиты, отсутствие дублей, передачу памяти в текстовые и фото-запросы и прежние правила ответа. API заменены тестовыми клиентами: токены и сеть для тестов не нужны.

Файлы `.env`, ключи доступа, SQLite-базы и резервные копии исключены через `.gitignore`.
